# P0 实施规格

状态：采用开发计划中的默认方案实施；需求变化按后续用户指示调整。

## 兼容范围

用户使用 realme，并希望兼容各品牌安卓手机。首版最低 Android 8.0（API 26），不绑定品牌，不依赖 Google Play 服务。不同品牌不等于所有历史系统均可支持，真机覆盖情况单独记录。第三方界面库包含原生二进制时保留多架构打包，并在发布阶段验证目标处理器兼容。

## 本轮确定的实施默认值

| 项目 | 实施值 |
| --- | --- |
| 工作名称 | 个人记账 |
| 开发包名 | com.personal.ledger；正式签名前固定 |
| 颜色 | 背景 #F6F7F9，文字 #1F2937，强调 #3563D9 |
| 支出分类 | 餐饮、电子物品、交通、日用品、学习、娱乐、其他支出 |
| 收入分类 | 生活费、工资、兼职、红包、其他收入 |
| 单笔金额 | 0.01—999999999.99 元；数据库存整数分 |
| 分类名称 | 1—20 个 Unicode 码点，去首尾空格，同收支类型内唯一 |
| 备注 | 0—500 个 Unicode 码点 |
| 日期 | Asia/Shanghai 的日历日期；首版仅今天及过去日期 |
| 比较 | 周一至周日、自然月；两周期可跨年，不能相同；A−B |
| 邮箱 | 仅 @qq.com；其他别名不在首版 |
| 用户名 | 4—32 个 ASCII 字母、数字或下划线，统一小写 |
| 密码 | 12—128 个字符，可粘贴；服务端成熟哈希，不明文落库 |

收入支出分类不得交叉引用；用户 ID 不从客户端载荷决定。所有本地写入必须同时生成持久待同步操作。当前阶段尚无真实账号，不向用户展示虚假“已同步”。

## 页面交付

关键视觉稿位于 `P0-页面视觉稿.html`，展示账本、分类选择、金额表单、比较、我的、登录。它是静态评审稿，演示金额不是用户数据，也不承担应用功能。

交互以根目录《页面结构与交互设计》为准：今日区域保持顶部、历史补记继承选中日期、记账必须主动选分类、离线本地保存成功即可返回、删除二次确认。

## P0 检查

- 视觉稿以本地浏览器实际渲染，检查内容截断、页面溢出和中文显示。
- 从 UI-01 至 UI-11 检查页面覆盖，辅助弹层和错误状态沿用交互文档。
- 没有 APK 的阶段仅报告设计检查，不将浏览器视觉稿称为安卓运行测试。

## 工程工具链

首轮采用经过兼容表核对的 JDK 17、Gradle 8.11.1、AGP 8.9.2、compile/target SDK 35。Kotlin 2.0.21 使用同版本 Compose 编译插件。该组合是确定的构建基线，不宣称为最新版本；公开上架前重新检查目标 SDK 要求。

参考：[AGP 8.9 兼容说明](https://developer.android.com/build/releases/agp-8-9-0-release-notes)、[Compose 编译插件说明](https://developer.android.com/jetpack/androidx/releases/compose-kotlin)。
