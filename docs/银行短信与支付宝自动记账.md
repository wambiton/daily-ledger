# 银行短信与支付宝自动记账（0.7.11 测试版）

## 开启

覆盖安装新版，保留已有数据。进入“我的 → 自动记账”，确认固定目标账本及自动记账总开关已开启，再打开“银行短信自动记账”，允许系统的短信权限请求。

短信只处理开启后新收到的消息，不读取历史短信。目前支持招商银行 95555、带“【招商银行】您账户…于…快捷支付/消费/存入/退款…”的已适配模板，不代表支持所有银行或所有招商银行短信。验证码、普通消息不保存。

## 入账与合并

- 普通消费记支出，存入记收入，退款另记收入而不冲减原支出。明确的本人互转、充值和提现不计收支。
- 沿用已确认的商户分类；短信没有分类规则时使用“其他支出”或“其他收入”，退款使用“退款”。
- 同一固定账本内，银行短信与微信/支付宝通知按渠道、金额、收支方向、退款标记及五分钟交易时间窗口一对一配对。两条来源只生成一笔统计；不会跨账本合并。
- 自动判断仍可能把相近的不同交易合并。进入“已处理”，查看账目与来源，选择“这不是同一笔，拆分此来源”，确认后保留两笔且均计入统计。重复打开或再次处理同一来源不会再次入账。
- 来源和合并关系保存在当前手机，正式账目按原有备份流程保存到电脑。

## 支付宝漏记如何核对

“连接与后台设置”会区分最近收到支付宝通知、最近匹配支付信息和未匹配原因。支持读取通知的大文本、多行文本和普通正文；普通聊天/营销消息不会因为出现数字就记账。

支付宝应用内的“支付消息”页面不等于手机发出了系统通知。若系统没有发通知或隐藏了金额，通知识别无法获取账单；符合已适配模板的银行卡短信可作为另一条来源。没有通知、也没有支持的短信时仍需手动补记。

请在下一次正常消费后核对金额、时间、目标账本和来源；无需为测试额外消费。程序测试与模拟合并通过不等于所有真实银行/支付宝通知模板均已验证。

## 0.7.12：查看接收与入账情况

首页的自动记账状态可点击进入详情。有待确认记录时会突出提示全手机待确认数量；首页和详情使用相同的权限、账本与连接状态判断。

在详情顶部点击“查看接收与入账情况”，分别查看微信、支付宝、银行短信：

1. **最近接收**：软件实际收到来源消息的时间。短信仅记录支持银行95555的接收时间，不代表所有银行。旧版本没有保存接收时间时会显示“尚无记录”。
2. **最近识别支付信息**：成功匹配交易模板的时间。此时可能仍需补全金额或分类，不能等同入账成功。
3. **最近记录结果**：从本手机识别记录读取“已入账、待确认、已合并、已忽略”，同时标出该记录的建立时间和原目标账本。后台排队可能使记录建立时间晚于收到消息的时间；记录可能属于更早的一笔，且账目之后可能已被修改或删除。

“处理这笔待确认”直接打开对应记录，不会改变自动记账的固定目标。展开或收起排查区域也不会修改开关或账本。

此面板不会推测没有收到的付款，不保存未匹配消息原文；它不代表电脑备份成功。银行短信权限、平台通知使用权、后台设置仍在原入口管理。


## 恢复手动忽略的记录

在自动记账的“已处理记录”中，手动选择过“不入账”的原记录可点击“恢复到待确认”，确认提示后到待确认列表核对。同笔已关联来源一起恢复，恢复本身不会写入账目、改变统计或授予以后自动记账的许可；需要在应用内重新确认。已有账目或来源状态不一致时会拒绝恢复，避免重复记账。

充值、提现、本人互转等系统排除项不提供此入口。已恢复记录收到晚到的关联来源也继续等待人工确认。该操作不改变当前查看账本或自动记账目标，记录仍归属于原指定账本。2026-11-09已通过realme独立模拟账本的恢复确认、取消和恢复后不立即入账页面测试；关联多来源及真实消息场景仍需单独验收。


## 撤销已入账的自动识别记录

在“已处理记录”中点击“撤销入账”并确认，对应账目移入回收站，不再计入收支和预算；同笔已关联来源一起标记撤销。来源证据和导入标识保留，重复点击不会再次删除或重新入账。需要找回时在回收站保留期内恢复；规则仍保留，若不希望后续自动匹配，请另行停用规则。

撤销后，前后5分钟内同渠道、同金额、同方向的消息保守进入待确认，不自动重建账目；这可能包含另一笔相同金额的真实消费，需要人工核对。不承诺拦截缺失交易时间、不同渠道或超出窗口的所有消息。回收站恢复后来源仍保留“已撤销”处理痕迹，旧撤销按钮重试不再次删除已恢复账目。2026-11-09已通过realme独立模拟账本的撤销确认、取消、移入回收站及来源保留页面测试；真实消息和多来源全流程仍需单独验收。


## 通知栏撤销入账

新版生成的已入账/已合并通知提供“撤销入账”按钮，点击后由后台队列将对应账目移入回收站，并取消同笔来源的通知；不必先打开应用。撤销是可恢复操作，需要找回时到回收站处理。重复点击或旧确认/改名动作不会重新入账或覆盖已撤销账目。系统支持时操作要求解锁，锁屏公开通知不包含操作按钮和账目详情。

尚未入账的通知仍提供确认/改名/忽略；缺少账目关联的异常通知不提供撤销按钮。系统可能折叠按钮，需展开通知；旧版已经发出的通知不会自动补上新按钮，可使用应用内撤销入口。若操作后没有明确变化，请打开应用核对，不要根据通知消失判断备份已成功。当前仅完成电脑开发验证，真实系统通知按钮和后台唤醒需后续手机专项测试。


## 已入账通知设置

自动记账 → 连接与后台设置 →“显示已入账结果通知”：默认开启，已入账和已合并的结果使用独立静默通知频道，仍可展开撤销。关闭后停止显示新结果并清除该频道现有通知；待确认通知继续保留。确认入账后即使结果通知关闭，也会移除该笔旧待确认提示。可在已处理记录中查看或撤销。

此设置只影响本手机的提示，不关闭自动记账，不修改账目，也不改变系统通知权限；系统禁止通知时仍无法显示待确认提示。旧版本已发出的结果通知可能仍留在旧频道，可手动划掉。真机提示音、通知折叠和开关页面尚待验收。


## 查看记录与规则说明

打开自动记账记录的确认或查看页面，可查看“记录与规则说明”：保留且仍与原指纹一致的规则会展示名称、渠道、商户、时段、星期和优先级。规则修改/删除后不使用新定义解释旧记录，缺少指纹时也不猜测命中情况。记录原处理原因仍保留；说明不重新匹配、不授予自动记账许可、不修改原账目。当前确认状态不能用来倒推过去授权，界面会明确区分。

## 在电脑上核对微信和支付宝账单

手机“文件导入导出”中选择正确账本和日期范围，导出 JSON。在 Windows 程序打开“微信／支付宝账单核对”，选择已解压的交易明细 CSV 或 XLSX，再选择 JSON。两份文件各不超过20MB。

同日同额的记录需要人工核对。程序会分别提示重复订单号、已导入的补记记录和回收站中的候选。原始支出与明确标注收入的退款分别核对。

确认某笔交易确实遗漏后，在本页选中“所选账本中未找到”的记录。可按住 Ctrl 多选同类交易，选定已有分类，再点击“导出已核实的选中记录”。只有带订单号且方向与分类相符的交易能导出。请保存到新文件名，再到手机“文件导入导出”选择该 JSON，核对预览后追加。同一平台同一订单重复导出沿用同一个标识，供手机检查重复。真实平台模板仍需用户试用验证。

Excel 账单中的长订单号需要以文本形式保存。若订单号为数值或公式，程序会要求人工核对，避免把丢失精度的编号作为重复判断依据。

选中同日同额的交易，点击“查看同日同额候选”核对分类、名称、备注和回收站状态。使用“仅看可导出的补记候选”可缩小列表。独立退款凭证按收入记录，原交易保留；相同订单的多条退款需要人工核对。科学计数法形式的订单号同样需要人工核对。

若同日同额的候选确实是另一笔真实消费，可在明细窗口核对后选择“已核实为另一笔交易，允许补记”，再次确认后选中该行并导出。此选择仅在本次预览有效。

手机追加导入的确认预览会显示文件内正常账目的日期范围、收入与支出合计。金额包含文件内重复项，不包含回收站；选择跳过重复后，实际追加金额可能更少。只有回收站或空文件时显示“无正常账目”。

手机导入要求文件为有效UTF-8编码的单个JSON对象。若提示编码异常或文件损坏，请重新导出，不要修改原账目来尝试导入。20MB上限按文件字节数计算；文件内拼接多个JSON或附加其他文本会被拒绝。
